# CUI DataGrid 能力推进与性能约束

## 1. 目标与边界

本文档用于推进 CUI `DataGrid` 的业务能力，使常用能力接近 WPF `DataGrid`，但不复制 WPF 的内部实现，也不把 WPF 的托管对象、反射和容器状态模型原样搬入 CUI。

推进目标按以下顺序排序：

1. 保持百万行、宽表、连续滚动和列宽调整的现有性能边界。
2. 补齐真实业务表格需要的列组织、编辑事务、列类型和扩展点。
3. 补齐可绑定、可主题化、可自动化和可测试的公开契约。
4. 只在语义有价值时兼容 WPF；C++ 所有权、AOT 和 retained-mode 布局优先采用 CUI 原生方案。

不以“公开成员数量相同”作为完成标准，也不要求复刻 WPF 的私有类层次、命令路由细节或反射路径。

## 2. 当前基线

当前 `DataGrid` 已具备：

- 百万行稀疏行虚拟化与可选列虚拟化；
- WPF 语义的 `FrozenColumnCount`，冻结 Header/Cell 与滚动列带共享稀疏投影；
- WPF 顺序的列头拖拽重排、可取消/可替换指示器事件与冻结区边界；
- Auto、SizeToCells、SizeToHeader、Pixel、Star 列宽和低延迟拖拽调整；
- Cell、FullRow、CellOrRowHeader 选择，区域化 SelectAll 和重复项身份保持；
- 当前单元格、键盘导航、多列排序；
- Text、CheckBox、Template 三种列及 WPF 语义的 Cell/Row 编辑事务；
- Grid、Table、Selection、Value、Scroll 等虚拟 UIA 能力；
- 动态 XAML、AOT 代码生成、主题和设计器基本闭环。

现有优势集中在运行时正确性与规模性能。主要缺口集中在公开扩展面、列显示模型和行级业务事务。

## 3. 不可退让的性能约束

### 3.1 复杂度约束

- 普通布局、滚轮、滚动条 Thumb 拖动和命中测试不得扫描总行数。
- 不得为未实现的行或单元格保存容器级状态；常驻空间保持在 `O(列数 + 已实现行数 × 已实现列数 + 稀疏选择元数据)`。
- 全选、百万行选择和集合变更继续使用区域/区间表达，禁止展开成 `行数 × 列数`。
- 列显示顺序映射只允许在列集合或显示顺序改变时 `O(C)` 重建；布局、绘制、键盘导航和 UIA 查询必须为 `O(1)` 映射或已有前缀上的 `O(log C)` 查询。
- 冻结列不得复制单元格树。冻结区和滚动区共享列定义、绑定和选择身份，只拆分已实现视觉投影。
- 行级编辑状态只允许保留活动事务，不得为每一数据行预建事务对象。

### 3.2 分配与失效约束

- 滚动、列宽 PointerMove、Cell hit-test 热路径不得新增按帧堆分配。
- 新事件在无订阅者时必须走无分配快速路径。
- 属性、样式或列顺序变化优先局部更新已实现 Header/Row；不能默认重建根模板或全量读取 ItemsSource。
- 自动列元数据对同一数据源模式最多处理一次；即使全部列被取消或元数据为空，也不得在每次行重建时重复反射。
- AOT Production 不为了模拟 WPF 动态反射而恢复名称查找；编译期列模式继续由代码生成器负责。

### 3.3 回归门禁

每个阶段至少保持以下门禁：

- `CUICoreTests` 全量通过；
- 百万行首帧、快速滚轮、Thumb 拖动、SelectAll、列宽拖动的结构化工作量不增长；
- 宽表列虚拟化继续只保留冻结前缀与视口连续滚动列带；
- Release 下关键场景多次测量的中位耗时原则上不得回退超过 5%；时钟噪声较大时以实现行/列数量、布局次数、源读取次数和分配次数作为硬判据；
- 新功能必须覆盖异常、所有者销毁、事件重入、ItemsSource 回滚和 UIA 身份失效边界。

## 5. 关键设计决定

### 5.1 列集合顺序不再等于显示顺序

M1 使用逻辑、显示和可见三个连续投影指向同一批列对象：逻辑序列保持插入/集合顺序，显示序列包含全部列并服务 WPF `DisplayIndex` 语义，紧凑可见序列只包含 `Visibility::Visible` 的列并服务导航和 UIA 坐标。每列保存显示下标和内部可见下标，所以热路径映射为 `O(1)`；不在每个 Cell 中复制映射。

显示序列仍持有 `unique_ptr`，但重排只旋转这些轻量句柄，堆上的 `DataGridColumn` 对象地址不会移动。程序化重排或未来拖拽释放时只提交一次 `O(C)` 旋转；PointerMove 不改列序列。与改造所有热路径去间接查询映射相比，这一方案让滚动、布局和命中测试继续使用连续数组直接下标。

重排时，CurrentCell、SelectedCells 和 UIA 继续按列对象身份对齐；UIA 虚拟节点 ID 不变，只更新坐标。顺序相关的宽度前缀会失效，但昂贵的 Auto/SizeToCells 内容采样随列句柄同步旋转，不会因为换位置重新读取数据源。

与 WPF 一致，Hidden 和 Collapsed 都不进入 DataGrid 的布局、导航和 UIA 表格投影，二者之间切换不改变可见投影；`DisplayIndex` 仍包含不可见列。隐藏期间保留列、CurrentCell/SelectedCells 和 UIA 身份，重新显示时复用原有虚拟节点 ID，但不保留不可见 Cell/Header 容器。

### 5.2 冻结列不创建第二套数据模型

冻结列只是水平视口的两个不相交已实现范围：原始 `DisplayIndex` 前缀 `[0, FrozenColumnCount)` 和视口附近的连续滚动列带。不可见列仍占冻结阈值位置，这与 WPF 的 `DataGridColumn.IsFrozen` 语义一致。绑定、列宽、排序方向、选择和自动化身份仍只有一份；行与表头只维护两段轻量指针投影，不复制单元格树或数据模型。

整个 Header/Row 内容继续随水平偏移移动，冻结视觉使用反向位移固定在原位；滚动列进入冻结区时在边界裁剪，并让冻结视觉保持更高的绘制与命中层级。滚动热路径复用变换存储，不新增逐帧、逐 Cell 堆分配。`BringColumnIntoView` 对冻结列不滚动，对普通列则把冻结宽度计入可用视口。

`FrozenColumnCount` 使用 DP 基值/有效值 coercion：负数严格拒绝，有效值限制到当前列数，列增加后可从保留的请求基值恢复。运行时自动生成列、声明式列、插入/删除、清空、显示重排和 ItemsSource 失败回滚都参与同一重算契约。Auto/SizeToCells 的延迟采样只覆盖冻结前缀与滚动列带，不扫描中间未实现列。

### 5.3 可编辑数据源采用可选接口

现有 `IBindingList` 保持只读、随机访问和通知核心，不直接增加所有实现都必须承担的写接口。新增行、删除行和事务编辑通过可选接口发现；不支持时 DataGrid 自动降级为只读集合行为。

### 5.4 自动列事件采用 C++ 所有权语义

`AutoGeneratingColumn` 的候选列由事件参数独占持有。处理器可取消或用另一个 `unique_ptr` 替换，不暴露 WPF 式由 GC 隐式接管的悬空所有权。`AutoGeneratedColumns` 不携带空 EventArgs，以避免无意义对象构造。M0 先开放 C++ API，不把这两个事件加入声明式 XAML；AOT 列早于普通 XAML 事件订阅生成，若直接暴露会产生构建模式相关的时序差异。声明式/AOT 定制统一留到 M3 的生成期列模式钩子。

动态事件只服务于允许运行时属性发现的构建。AOT Production 的列定制在设计器/代码生成阶段完成，不为表面一致性引入运行时名称反射。

M3 使用严格的 `CuiDataGridAutoColumns` 生成期 catalog 实现这条边界。规则按静态 `DataType + Property` 匹配，并可用显式 `GridName` 对单个网格覆盖类型级规则；具名规则优先。catalog 只进入 `CuiCodeGen` 主机，先变换或抑制默认候选列，再发出普通的确定性列构造与编译路径。Production 不链接 catalog、不解析 XML，也不安装运行时回调或名称注册表。

## 6. M0 验收标准

- 每个可读属性最多触发一次 `AutoGeneratingColumn`；处理器可修改候选列、替换列或取消。
- 所有候选处理完成并安全提交后，`AutoGeneratedColumns` 恰好触发一次。
- 事件中删除 DataGrid、抛出异常、改变列模式或导致 ItemsSource 事务失败时，不留下部分列、错误 owner 或待触发事件。
- 无订阅者时保持当前直接生成路径，不创建事件快照。
- 同一数据源全部属性被取消、没有可读属性或元数据为空时，不在后续行重建中重复扫描。
- 事件不会因滚动、回收行、列宽调整、排序或选择变化再次触发。

## 7. M1a 验收标准

- `GetColumn(index)` 保持逻辑/插入顺序；`GetColumnFromDisplayIndex(index)` 返回视觉顺序；两者均为 `O(1)`。
- 附着前设置 DisplayIndex 会在 Adopt/Add 时一次定位；附着后可通过列 Setter 或 DataGrid Move API 程序化重排。
- 重排不改变列对象地址、逻辑顺序、CurrentCell 列身份、SelectedCells 列身份或 UIA 虚拟节点 ID。
- Header、Cell、排序、编辑、列宽、命中测试、虚拟化和 UIA 坐标统一使用显示下标。
- 无订阅者时不创建显示顺序事件参数；事件只在成功提交后触发，并允许安全重入或销毁所有者。
- 重排不清空 Auto/SizeToCells 内容宽度采样；结构工作量只与列数和已实现行/列数有关，不读取总行数。

## 8. M1b 验收标准

- `Visibility` 支持 Visible、Hidden、Collapsed；Hidden/Collapsed 都退出 Header、Cell、宽度、命中测试、键盘导航和 UIA 行列投影，`DisplayIndex` 仍包含全部列。
- 可见性只在列边界切换时重建 `O(C)` 紧凑投影；Hidden 与 Collapsed 互换不重建视觉，不读取 ItemsSource，也不为不可见列生成 Cell。
- `InsertColumn` 按逻辑位置插入并一次定位显示位置；`RemoveColumn` 按逻辑下标或列身份安全分离并返回 `unique_ptr` 所有权。
- 插入、删除、隐藏和恢复不改变未受影响列的对象地址、CurrentCell/SelectedCells 列身份、Auto 内容宽度采样或 UIA 虚拟节点 ID。
- XAML/设计文档、运行时物化和 AOT 生成均支持列 Visibility；非法值保持严格拒绝。
- 删除、可见性切换和 ItemsSource 回滚允许事件重入或销毁所有者，不恢复已经被重入永久删除的列指针。

## 9. M1 冻结列验收标准

- `FrozenColumnCount` 只接受非负整数；有效值 coercion 到当前列数且保留请求基值，列重新增加或自动生成后恢复；`IsFrozen` 以包含不可见列的原始 `DisplayIndex` 为准。
- 冻结 Header/Cell 在近端、部分重叠和远端水平滚动时保持原位与对象身份；滚动列在冻结边界同时裁剪绘制和命中，冻结列 `BringColumnIntoView` 不改变偏移。
- 开启列虚拟化时每行只实现冻结前缀与视口滚动列带，空间与更新工作量保持 `O(冻结列数 + 视口列数)`；不创建第二套 Cell 树，也不扫描中间列。
- Auto/SizeToCells 的延迟内容采样覆盖冻结列和滚动列带，连续小幅滚动保持变换更新且不重复读取数据源。
- 动态 XAML、设计文档、运行时物化、AOT 代码生成与静态生成样例均支持 `FrozenColumnCount`，负值在设计与运行时严格拒绝。
- 1000 列 × 100 万行门禁覆盖冻结对象/位置稳定、边界裁剪、尾列编辑与 UIA 稀疏访问；Release 全量回归保持通过。

## 10. M1 用户列重排验收标准

- `CanUserReorderColumns` 与列级 `CanUserReorder` 只约束用户手势；程序化 `DisplayIndex`/`MoveColumn` 继续可用。
- 列头按下后仅在水平位移超过 4 DIP 时升级为拖拽；事件顺序保持 `ColumnHeaderDragStarted` → `ColumnReordering` → 零到多次 `ColumnHeaderDragDelta` → `ColumnHeaderDragCompleted` → `ColumnDisplayIndexChanged` → `ColumnReordered`。
- `ColumnReordering` 可取消事务，也可用 `unique_ptr<Control>` 替换拖拽与落点指示器；Presenter 在结束、取消、架构变化和所有者销毁时严格回收临时视觉。
- PointerMove 只更新指示器几何并在可见列/宽度前缀上做 `O(log C)` 命中；不改变显示投影、不重建数据行、无逐帧堆分配，释放时才提交一次 `O(C)` 旋转。
- 冻结列与非冻结列不能互跨边界；隐藏列仍参与原始 DisplayIndex 插入位置，垂直越界、捕获丢失、资格变化和显式取消均发布取消完成事件且不提交。
- 事件中重入移动/删除列或销毁 DataGrid/Header Presenter 不继续访问失效对象；完成事件后仅按仍受所有者持有的列身份提交。
- 动态 XAML、设计文档、运行时物化、AOT 代码生成、Designer 事件目录和 Demo 均支持网格/列级重排配置与拖拽事件。

## 11. M2 行级编辑事务验收标准

- 增加 `DataGridEditingUnit::Cell/Row`、带编辑单元的提交/取消重载、`RowEditEnding` 和只读 `DataGridRow::IsEditing`；参数为空的提交/取消与 WPF 一致，先处理活动 Cell，再处理活动 Row。
- 同一时刻只保留一个活动行事务。Cell 提交把值写入源但不结束行事务；Row 取消可回滚该行中已经提交的多个 Cell，Row 提交才结束源事务。
- 编辑事件顺序保持 `CellEditEnding` 在 `RowEditEnding` 之前；任一 ending 事件取消时不越过对应提交/取消边界，`CommitEdit(Row, false)` 提交后立即为同一行开启新事务。
- 数据源编辑采用可选 `IEditableBindingSource` 能力；`ObservableObject` 与编译期 `CompiledBindingRecord` 均提供当前记录快照。未实现该接口的源仍可编辑 Cell，但 Row 取消只能结束 UI 事务，已写回的值不伪装成可回滚。
- 活动行按数据项与重复项 occurrence 身份跟踪，索引变化时重映射；离开活动行、排序和只读切换先安全结束事务。活动行可离开视口但不保留行容器，也不为其他数据行创建事务状态。
- ItemsSource/集合变更、活动项删除、虚拟化回收、源回调异常、事件重入和所有者销毁不继续访问失效对象；回调异常可重试，失效事务以回滚优先且不发布过期结束事件。

## 21. M3 自动列 AOT 定制验收标准

## 22. M4 Current 投影与 ScrollIntoView 验收标准

- `CurrentItem`、`CurrentColumn` 与 `CurrentCell` 都是可读写、可观察的强类型依赖属性；三个投影共享唯一 `_currentCell` 稳定身份，不建立第二套 currency 状态。`CurrentItem` 等价于 `CurrentCell.Item`，空 `CurrentColumn` 表示只保留当前行，`CurrentCell` 接受完整、仅行、仅列和空的 WPF partial identity。
- 外部赋值按数据项引用与 occurrence token 解析当前视图位置，并校验列仍归当前 DataGrid 所有；完整 Cell 切换继续经过既有 Cell/Row 提交门禁。ItemsSource 替换、排序、Move 与列投影变化按稳定身份重映射，定位索引变化会刷新 DP/TwoWay 源，但同一 item/column 不误发逻辑 `CurrentCellChanged`。
- 三个 DP 在 Production 代码生成中使用 `DataGrid::CurrentItemProperty()`、`CurrentColumnProperty()` 与 `CurrentCellProperty()` 精确身份；不恢复属性名反射。计算型 getter 的目标通知直接读取已提交投影并保留 Binding 表达式，普通源到目标、目标到源及 partial identity 往返均有专项回归。
- `ScrollIntoView(item)` 只执行垂直定位；`ScrollIntoView(item, column)` 支持 item/column 任一为空以分别执行水平或垂直定位，两者都存在时组合完成。数据项按 occurrence 稳定定位，列按对象所有权与可见性校验；虚拟行只实现目标窗口，宽表通过已维护宽度前缀定位，不线性扫描中间行或列。
- Demo 使用三个 OneWayToSource 绑定公开当前投影，并在百万行模式组合定位尾项与目标列；TwoWay partial identity、排序定位刷新、虚拟行列、非法/外来/不可见列和 AOT 精确 DP 均有回归，`CUICoreTests` 749/749 通过。

## 23. M4 路由命令与剪贴板验收标准

- `BeginEditCommand`、`CommitEditCommand`、`CancelEditCommand` 由 DataGrid 类命令绑定统一接入现有编辑事务；`DeleteCommand`、`CopyCommand` 分别复用 `ApplicationCommands::Delete()` 与 `ApplicationCommands::Copy()` 的稳定身份，并提供 F2、Escape、Delete、Ctrl+C 默认手势。CanExecute 同步网格有效态、编辑态、选择与策略变化，编辑控件拥有 Ctrl+C 时继续路由而不劫持文本复制。
- Commit/Cancel 未指定参数时按 WPF 语义在活动 Cell 编辑中解析为 Cell，否则解析为 Row；删除命令复用可编辑列表、占位行、排序视图 occurrence 与批量删除门禁，不建立第二套编辑或删除状态机。
- `ClipboardCopyMode` 为默认 `ExcludeHeader` 的严格三值依赖属性；复制按可见列显示顺序和选区包围框输出，未选择 Cell 留空、完全未选择的行跳过，`IncludeHeader` 增加列头。每个 Header/Data 行均触发可修改的 `CopyingRowClipboardContent`，TemplateColumn 或应用可替换、删除或追加字段。
- 复制通过选区流式两遍构造 Unicode TSV，不先物化整个选区；候选矩阵和事件后实际字段总量上限均为 1,000,000 Cell，UTF-16 文本上限为 16 Mi 字符。字段中的制表符、换行与引号使用 TSV 引号规则；ItemsSource、选择或列模式在回调中重入变化时原子放弃发布。
- Demo 启用 `IncludeHeader` 并说明 Ctrl+C 行为；Production 代码生成使用 `DataGrid::ClipboardCopyModeProperty()` 精确身份。命令身份/手势/门禁、编辑控件所有权、稀疏百万候选拒绝、事件改写、转义与内存剪贴板发布均有专项回归，`CUICoreTests` 751/751 通过。M4 下一子项为 Grid/Column 级样式与模板。

## 24. M4 Grid/Column 样式与模板验收标准

## 25. M5 RowDetails 与行生命周期验收标准

- `DataGrid` 提供默认值为 `VisibleWhenSelected` 的 `RowDetailsVisibilityMode` 与强类型 `RowDetailsTemplate`；详情内容只在已实现且策略可见的 `DataGridRow` 内创建，模式变为 `Collapsed`、选择离开、模板替换或行退出实现集时立即销毁 presenter 与生成视觉。

## 26. M5 GroupStyle 分组专项验收标准

- `DataGrid` 直接复用传入的 `CollectionViewSource`，其占位行适配视图继续转发 `IBindingListGroupView` 的分组元数据与变更通知；通用自定义分组源同样保留 GroupStyle 能力，不具备可变排序契约的分组源显式拒绝可能破坏分组区间的全局排序。

## 27. M6 RowDetails 冻结与可观察生命周期验收标准

- `AreRowDetailsFrozen` 是默认 `false` 的强类型依赖属性；开启后 Details presenter 以当前水平偏移做反向补偿，和行头/冻结列共享滚动更新时机，只遍历已实现行且不重建 Row、Cell、Details 或读取 ItemsSource。

## 29. M6 行高与用户调整验收标准

- `CanUserResizeRows` 是默认 `true` 的强类型依赖属性，控制行头鼠标调整与双击自动恢复；`MinRowHeight` 默认 `0`，只接受有限非负值，并优先约束 Grid 的 `RowHeight` 与用户覆盖高度。属性变化原位更新已实现行与虚拟滚动度量，不重建 Row/Cell/Header。
- 行头底部分隔线调整当前行，顶部分隔线调整上一已实现行；拖动使用 render-space 位移、捕获丢失/Cancel 回滚，双击清除该 occurrence 的用户高度。热区在紧凑自定义行头上保留中间选择区域，`CanUserResizeRows=false` 时不显示 SizeNS 光标也不进入事务。
- 用户高度只写入 Cell 基线 presenter；RowDetails 继续按内容测量并与基线相加，拖动、自动恢复和 `MinRowHeight` 变化都保持 Row 与 DetailsElement 身份。固定/用户高度继续走 DataGridCellsPresenter 的固定高度快速布局。
- 只为实际调整的 item occurrence 保存覆盖；虚拟宿主接收排序后的稀疏 extent 投影，用前缀差值和二分查询修正行顶点、单行高度、分组区间与总 extent。回收、BringIntoView 和源 Move 后覆盖跟随 occurrence，删除后立即裁剪；PointerMove 复用预留存储，不扫描 ItemsSource、不创建逐行高度表。
- 动态 XAML、Designer 属性目录、严格往返、运行时物化、Production AOT 与 Demo 使用 `CanUserResizeRowsProperty()`/`MinRowHeightProperty()` 精确身份；代码生成契约升级至 78。行头事务、详情合成、稀疏虚拟化、源移动/删除及自动列源替换身份回归闭环，`CUICoreTests` 771/771 通过。M6 完成。

## 30. M7 Grid 级列宽默认验收标准

- `ColumnWidth` 默认 `SizeToHeader`，`MinColumnWidth` 默认 `20`，`MaxColumnWidth` 默认正无穷；三者均为强类型依赖属性。`ColumnWidth` 接受 Auto、SizeToHeader、SizeToCells、非负 Pixel 与 Star，Min/Max 遵循 WPF 的非负、NaN/Infinity 验证边界。
- `DataGridColumn.Width` 未设置时以 `Auto` 作为独立声明默认并继承 Grid `ColumnWidth`；列级 Width/MinWidth/MaxWidth 一旦显式设置即覆盖对应 Grid 默认，Clear 后恢复继承。用户拖动只把实际受影响列提升为本地宽度，不污染其余列。
- 显示宽度按 `DataGridColumn.MaxWidth`、`DataGrid.MaxColumnWidth`、`DataGridColumn.MinWidth`、`DataGrid.MinColumnWidth` 的 WPF 优先级约束；矛盾 Min/Max 仍保持有序布局边界，最高优先级 Max 获胜，不进入 `std::clamp` 未定义区间。
- Grid 默认变化只清除继承列的 resolved width、宽度前缀和已实现 Header/Cell 投影；不重建 Row/Cell，不清空 Auto/SizeToCells 内容样本，不读取全量 ItemsSource。百万行门禁验证属性切换保持视口级读取预算。
- 严格 XAML/DesignValue 独立保存列 Width/MinWidth/MaxWidth 是否真正出现，省略属性的列在动态物化和 Production AOT 都继续继承 Grid；旧设计文档按原有总是发出 Setter 的语义兼容解码。
- Designer 属性目录、严格往返、运行时物化、Production AOT 与 Demo 使用三个精确 DP；Demo 以 Grid `*` 默认和列级 Pixel/Star 覆盖展示优先级。代码生成契约升级至 79，`CUICoreTests` 773/773 通过。M7 下一步进入共享行/详情选择器扩展。

## 31. M7 行/详情选择器扩展验收标准

- 增加共享 `IItemStyleSelector`/`ItemStyleSelectorReference`，并在 `DataGrid` 提供 `RowStyleSelector`、`RowHeaderTemplateSelector`、`RowDetailsTemplateSelector` 强类型依赖属性；RowStyle 与 RowStyleSelector 按 WPF 规则互斥，行头/详情的显式 Template 优先于 Selector，Selector 返回空时不越级制造视觉。

- 行头、详情 Presenter 和行样式在容器索引移动及跨索引回收时重新选择；相同模板身份仍重定向到新 item，同一 item 的普通可见性刷新不重复 Build。选择器回调以强引用固定策略，并在返回后复核弱生命周期、owner、item/index 与修订号，销毁 owner 或重入替换策略时不应用过期结果。
- WPF Selector 通常是应用代码类型；CUI 的适用子集继续在 Production AOT 生成树完成后由 C++ 挂接，不引入运行时名称反射。静态 RowStyle/RowHeaderTemplate/RowDetailsTemplate 仍由严格 XAML、Designer、动态物化与 AOT 验证，三个 Selector 使用精确 DP 身份但不作为可浏览的声明式值；代码生成契约升级至 80。
