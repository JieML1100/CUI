# CUI DataGrid 能力推进与性能约束

## 1. 目标与边界

本文档用于推进 CUI `DataGrid` 的业务能力，使常用能力接近 WPF `DataGrid`，但不复制 WPF 的内部实现，也不把 WPF 的托管对象、反射和容器状态模型原样搬入 CUI。

推进目标按以下顺序排序：

1. 保持百万行、宽表、连续滚动和列宽调整的现有性能边界。
2. 补齐真实业务表格需要的列组织、编辑事务、列类型和扩展点。
3. 补齐可绑定、可主题化、可自动化和可测试的公开契约。
4. 只在语义有价值时兼容 WPF；C++ 所有权、AOT 和 retained-mode 布局优先采用 CUI 原生方案。

不以“公开成员数量相同”作为完成标准，也不要求复刻 WPF 的私有类层次、命令路由细节或反射路径。

## 2. 当前基线

当前 `DataGrid` 已具备：

- 百万行稀疏行虚拟化与可选列虚拟化；
- Auto、SizeToCells、SizeToHeader、Pixel、Star 列宽和低延迟拖拽调整；
- Cell、FullRow、CellOrRowHeader 选择，区域化 SelectAll 和重复项身份保持；
- 当前单元格、键盘导航、多列排序；
- Text、CheckBox、Template 三种列及单元格提交/取消编辑；
- Grid、Table、Selection、Value、Scroll 等虚拟 UIA 能力；
- 动态 XAML、AOT 代码生成、主题和设计器基本闭环。

现有优势集中在运行时正确性与规模性能。主要缺口集中在公开扩展面、列显示模型和行级业务事务。

## 3. 不可退让的性能约束

### 3.1 复杂度约束

- 普通布局、滚轮、滚动条 Thumb 拖动和命中测试不得扫描总行数。
- 不得为未实现的行或单元格保存容器级状态；常驻空间保持在 `O(列数 + 已实现行数 × 已实现列数 + 稀疏选择元数据)`。
- 全选、百万行选择和集合变更继续使用区域/区间表达，禁止展开成 `行数 × 列数`。
- 列显示顺序映射只允许在列集合或显示顺序改变时 `O(C)` 重建；布局、绘制、键盘导航和 UIA 查询必须为 `O(1)` 映射或已有前缀上的 `O(log C)` 查询。
- 冻结列不得复制单元格树。冻结区和滚动区共享列定义、绑定和选择身份，只拆分已实现视觉投影。
- 行级编辑状态只允许保留活动事务，不得为每一数据行预建事务对象。

### 3.2 分配与失效约束

- 滚动、列宽 PointerMove、Cell hit-test 热路径不得新增按帧堆分配。
- 新事件在无订阅者时必须走无分配快速路径。
- 属性、样式或列顺序变化优先局部更新已实现 Header/Row；不能默认重建根模板或全量读取 ItemsSource。
- 自动列元数据对同一数据源模式最多处理一次；即使全部列被取消或元数据为空，也不得在每次行重建时重复反射。
- AOT Production 不为了模拟 WPF 动态反射而恢复名称查找；编译期列模式继续由代码生成器负责。

### 3.3 回归门禁

每个阶段至少保持以下门禁：

- `CUICoreTests` 全量通过；
- 百万行首帧、快速滚轮、Thumb 拖动、SelectAll、列宽拖动的结构化工作量不增长；
- 宽表列虚拟化继续只保留视口连续列带；
- Release 下关键场景多次测量的中位耗时原则上不得回退超过 5%；时钟噪声较大时以实现行/列数量、布局次数、源读取次数和分配次数作为硬判据；
- 新功能必须覆盖异常、所有者销毁、事件重入、ItemsSource 回滚和 UIA 身份失效边界。

## 5. 关键设计决定

### 5.1 列集合顺序不再等于显示顺序

M1 使用两个连续序列指向同一批列对象：逻辑序列保持插入/集合顺序，显示序列服务布局、命中测试、键盘导航和 UIA 热路径。每列保存当前显示下标，所以逻辑列到显示位置也是 `O(1)`；不在每个 Cell 中复制映射。

显示序列仍持有 `unique_ptr`，但重排只旋转这些轻量句柄，堆上的 `DataGridColumn` 对象地址不会移动。程序化重排或未来拖拽释放时只提交一次 `O(C)` 旋转；PointerMove 不改列序列。与改造所有热路径去间接查询映射相比，这一方案让滚动、布局和命中测试继续使用连续数组直接下标。

重排时，CurrentCell、SelectedCells 和 UIA 继续按列对象身份对齐；UIA 虚拟节点 ID 不变，只更新坐标。顺序相关的宽度前缀会失效，但昂贵的 Auto/SizeToCells 内容采样随列句柄同步旋转，不会因为换位置重新读取数据源。

### 5.2 冻结列不创建第二套数据模型

冻结列只是水平视口的两个已实现范围。绑定、列宽、排序方向、选择和自动化身份仍只有一份。布局阶段分别投影冻结区与滚动区，避免每行重复分配列集合。

### 5.3 可编辑数据源采用可选接口

现有 `IBindingList` 保持只读、随机访问和通知核心，不直接增加所有实现都必须承担的写接口。新增行、删除行和事务编辑通过可选接口发现；不支持时 DataGrid 自动降级为只读集合行为。

### 5.4 自动列事件采用 C++ 所有权语义

`AutoGeneratingColumn` 的候选列由事件参数独占持有。处理器可取消或用另一个 `unique_ptr` 替换，不暴露 WPF 式由 GC 隐式接管的悬空所有权。`AutoGeneratedColumns` 不携带空 EventArgs，以避免无意义对象构造。M0 先开放 C++ API，不把这两个事件加入声明式 XAML；AOT 列早于普通 XAML 事件订阅生成，若直接暴露会产生构建模式相关的时序差异。声明式/AOT 定制统一留到 M3 的生成期列模式钩子。

动态事件只服务于允许运行时属性发现的构建。AOT Production 的列定制在设计器/代码生成阶段完成，不为表面一致性引入运行时名称反射。

## 6. M0 验收标准

- 每个可读属性最多触发一次 `AutoGeneratingColumn`；处理器可修改候选列、替换列或取消。
- 所有候选处理完成并安全提交后，`AutoGeneratedColumns` 恰好触发一次。
- 事件中删除 DataGrid、抛出异常、改变列模式或导致 ItemsSource 事务失败时，不留下部分列、错误 owner 或待触发事件。
- 无订阅者时保持当前直接生成路径，不创建事件快照。
- 同一数据源全部属性被取消、没有可读属性或元数据为空时，不在后续行重建中重复扫描。
- 事件不会因滚动、回收行、列宽调整、排序或选择变化再次触发。

## 7. M1a 验收标准

- `GetColumn(index)` 保持逻辑/插入顺序；`GetColumnFromDisplayIndex(index)` 返回视觉顺序；两者均为 `O(1)`。
- 附着前设置 DisplayIndex 会在 Adopt/Add 时一次定位；附着后可通过列 Setter 或 DataGrid Move API 程序化重排。
- 重排不改变列对象地址、逻辑顺序、CurrentCell 列身份、SelectedCells 列身份或 UIA 虚拟节点 ID。
- Header、Cell、排序、编辑、列宽、命中测试、虚拟化和 UIA 坐标统一使用显示下标。
- 无订阅者时不创建显示顺序事件参数；事件只在成功提交后触发，并允许安全重入或销毁所有者。
- 重排不清空 Auto/SizeToCells 内容宽度采样；结构工作量只与列数和已实现行/列数有关，不读取总行数。
